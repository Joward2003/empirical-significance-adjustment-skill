# 审计模型与哈希边界

## 什么是哈希

哈希可以理解为文件内容的“数字指纹”。例如 SHA-256 会把任意文件转换成固定长度的
十六进制字符串；文件哪怕只改一个字符，结果通常也会完全不同。它适合核对“现在这份文件
是否仍是当时那份文件”，但不能恢复原文，也不是加密。

## 本 Skill 如何使用哈希

- `project.json` 和方法注册表的 SHA-256 被写入 baseline snapshot。
- 每一条批准运行和审计事件都保存前一条记录的哈希与自身哈希，形成追加式链。
- `verify_run_integrity.py` 会验证项目、注册表、Schema、baseline绑定和两条日志链。
- 最终报告列出关键运行文件的 SHA-256，便于提交时外部归档。

## 不能声称什么

本地哈希链不是不可篡改账本。拥有所有本地文件写权限的人可以同时改写 snapshot、日志和
哈希。需要更强证据时，应把关键哈希提交到受保护远端、机构存档或数字签名/时间戳服务。

## 运行顺序

1. 验证项目并初始化运行目录。
2. 复现、锁定并追加唯一 baseline。
3. 只追加有独立诊断依据的批准规格。
4. 把事后 p 值选择或失败尝试写入审计事件，而非批准日志。
5. 验证完整性，再生成最终报告。
